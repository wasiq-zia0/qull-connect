Maintain Qull Connect API documentation from the applications, not an embedded
or hand-authored specification. This file supersedes the original import brief.

1. Read README.md, STATUS.md, docs/INTEGRATION.md, docs/DOMAIN_REVIEW.md and each
   changed service's application/tests.
2. Complete and verify the behavior change before describing it as available.
   Never infer successful recovery, authenticated isolation, a saved card or a
   settled payment from a health response or user-facing prose.
3. Run tools/export_openapi.py using its current command-line interface to
   export all ten specs from the isolated actual FastAPI applications. Preserve
   owner-bound Bearer authentication and correct server/path composition.
4. Copy each generated openapi/<slug>.json to the corresponding website
   connect/<folder>/api-docs/<slug>.json. Folder names are in
   docs/connector-content.json. Do not prepend /api to paths that already have it.
5. Update docs/connector-content.json when the actual product scope, inputs,
   deliverables, limitations or fee changes. Run:
   python docs/build_documentation.py --site /path/to/qull_site
6. The generator renders product/guide/policy pages, service READMEs, manifests'
   descriptive fields and submission worksheets. It does not generate OpenAPI,
   create fake test results or deploy. Runtime MCP schemas must be exported from
   the actual tools after their signatures change; do not hand-copy stale schemas.
7. Check internal links, desktop/mobile layout, Swagger loading, real auth
   examples, fee/currency consistency, payment consent, data deletion and errors.
   The public reference is read-only; use an isolated test environment to mutate.
8. Commit only connector-scoped site files to the existing Qull website repo.
   Preserve unrelated live pages and configuration. Record the exact backend,
   docs and deployed versions so reviewers receive a consistent build.
9. Keep production verification, Stripe provider test evidence, legal finalization
   and Meta approval separate. Update STATUS.md only with evidence actually held.

Do not claim OAuth, live Gmail scanning, unattended triggers, automatic sending,
provider negotiation, claim filing, state-database searches or automatic annual
renewal unless the code implements it and the workflow is genuinely verified.
